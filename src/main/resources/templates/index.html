Essbase Java API Evolution

Changes to classes, interfaces, methods, and more in the Essbase Java API over time

Reading this table

For each version of the JAR, there are several sections: added, modified, removed, and deprecated. The added section lists classes/interfaces that have been added that were not present in the previous version of the jar. Public methods for each class are also listed (since they are also new by definition). The modified section lists classes/interfaces that have been modified in some way, typically because a method in that object has been added, removed, or changed (new arguments, return type, or some other change). The removed section lists objects that have been removed. Lastly, the deprecated section lists objects and their methods that have been marked as deprecated).

Note that the change analyzer lists both base classes (such as EssCube as well as the more commonly used interface object for the corresponding class (such as IEssCube). Typically in the Essbase Java API, all operations are performed with interfaces. While you typically shouldn't program with the base classes, they are in fact public and are occasionally used.

New methods appear in green, removed methods are in red, deprecated are marked with strike-through.
